# 05. 自定义通信协议规格

> D1 · 2026-09-23 · 协议 v1 设计基线，尚无设备实现。适用于项目模拟器及测试环境；不兼容性修改必须升级版本并同步两端、向量和测试。

## 1. 编码约定

所有多字节整数、IEEE-754 浮点的位模式及 CRC 字段均按大端传输。禁止直接发送 C++ struct，避免 padding、对齐和宿主字节序差异。时间戳为 UTC Unix 毫秒 uint64；v1 仅接受 0–9223372036854775807，超出范围拒绝，避免写入 SQLite 有符号整数时溢出；0 表示发送端时间未知，接收端单独记录接收时间。CRC 不承担认证或加密。

## 2. 帧布局

| 偏移 | 字段 | 字节数 | 规定 |
|---:|---|---:|---|
| 0 | Magic | 2 | AA 55 |
| 2 | Version | 1 | 01 |
| 3 | Type | 1 | 见下表 |
| 4 | Seq | 4 | uint32，发送方向独立递增 |
| 8 | PayloadLen | 2 | N，0≤N≤4096；不含固定头和 CRC |
| 10 | Timestamp | 8 | UTC 毫秒 |
| 18 | Payload | N | 按 Type 编码 |
| 18+N | CRC32 | 4 | 覆盖偏移 [0,18+N)，包括 Magic，不含 CRC 本身 |

固定头 18B，总帧长 22+N，最小 22B、最大 4118B。4096 是载荷上限，不是整个帧上限。

## 3. CRC

使用 CRC-32/ISO-HDLC：width=32、poly=0x04C11DB7、init=0xFFFFFFFF、refin=true、refout=true、xorout=0xFFFFFFFF。按位右移实现的反射多项式为 0xEDB88320；每字节低位先入，最终异或，不额外重复反射。CRC 数值以大端四字节附在帧尾。

已知检查值：ASCII 123456789 → 0xCBF43926；空字节序列 → 0。不得混用 CRC32C。测试需使用独立固定向量，不能仅做编码器与解码器互相验证。

## 4. 消息类型

| Type | 名称 | 方向与载荷 |
|---|---|---|
| 0x01 | HEARTBEAT | 双向，空载荷；TCP/串口各端每 1000ms 主动发送，不逐包回声 |
| 0x02 | TELEMETRY | 设备→客户端，非空 TLV 序列 |
| 0x10 | COMMAND | 客户端→设备，命令头与参数 TLV |
| 0x11 | COMMAND_ACK | 设备→客户端，固定 4B |
| 0x20 | DEVICE_INFO | 保留，v1 不发送；收到按未知类型跳过 |
| 0x30 | ERROR_REPORT | 保留，v1 不发送；错误通过 ACK/本地日志处理 |

仅支持类型且载荷有效才刷新 lastValidReceive。空 TELEMETRY 非法。未知类型 CRC 正确时完整跳过并记录计数，不把其载荷作为业务数据。

### 4.1 TELEMETRY

每个 TLV 为 metric_id:uint16 + value_type:uint8 + len:uint8 + value:len 字节；载荷恰好消费至末尾。

| value_type | 类型 | len |
|---|---|---:|
| 0x01 | float32，IEEE-754，有限值 | 4 |
| 0x02 | uint32 | 4 |

| metric_id | 名称 | 类型 | 单位 |
|---:|---|---|---|
| 1 | temperature | float32 | °C |
| 2 | pressure | float32 | kPa |
| 3 | voltage | float32 | V |
| 4 | rpm | uint32 | r/min |

一帧允许指标子集，标准模拟负载每帧包含四项，共 32B 载荷、54B 总长。真实超阈值有限数必须交给告警，不能当协议坏值过滤。

先校验 TLV 头和剩余长度，再读取值。已知指标的类型/长度不匹配、同帧重复 metric_id、NaN/Infinity、尾部不足一个完整 TLV，整帧拒绝。未知 metric_id 仅在结构合法时按 len 跳过并计数；若没有任何已知有效指标，则不更新遥测时间，仍可作为结构有效 TELEMETRY 更新存活。

### 4.2 COMMAND

载荷：command_id:uint16 + parameter_count:uint16 + parameter_count 个 TLV。TLV 使用与遥测相同的头，ID 属于独立的命令参数空间。

| command_id | 名称 | 参数 | 模拟器行为 |
|---:|---|---|---|
| 1 | Start | 0 个 | 开始遥测，心跳始终保持 |
| 2 | Stop | 0 个 | 停止遥测，仍可收命令/发心跳 |
| 3 | Reset | 0 个 | ACK 后恢复 100ms 周期与业务计数，并启动遥测；连接/帧序号不重置 |
| 4 | SetParameter | 恰好 1 个 | param_id=1，type=uint32，len=4，sample_period_ms∈[100,1000] |

未知命令、参数、重复参数或越界不能执行。结构可完整解析的请求返回拒绝 ACK；结构不完整的请求整帧丢弃、日志记录。SetParameter 不负责修改上位机告警配置。

### 4.3 COMMAND_ACK

载荷固定为 command_id:uint16 + status:uint16；status：0 成功，1 未支持命令，2 参数非法，3 设备忙，4 执行失败。其他 status 值语义未定义，接收端按载荷错误整帧丢弃，不关联命令（该命令到点按超时、结果未知处理）。

参数 TLV 的 len 为 1 字节：值超过 255B 的参数无法编码，发送端以本地 Failed 终结，不截断长度字段发出畸形帧。

ACK 头部 Seq 必须回显 COMMAND 的 Seq，不消耗设备自身普通发送序列。仅在当前 TCP/串口会话、设备和 command_id 匹配时关联，不能用“收到任意 ACK”判成功。默认等待 2000ms；不自动重发。设备同会话相同 Seq+内容的重复请求复用结果，不重复执行。同 Seq 内容不同拒绝。客户端生命周期见 [LLD 第 4 节](04_DETAILED_DESIGN.md)。

普通帧发送序号按模 2^32 递增；命令端在完整序号空间用尽前新建会话。序号不承诺持久化唯一性，数据库另用 session_id。

## 5. 固定测试向量

以下为完整十六进制帧（含 CRC），由独立 CRC 检查和 Python zlib 交叉核对；不表示项目解码器已通过测试。

空 HEARTBEAT，Seq=1，Timestamp=0，22B：

```text
aa 55 01 01 00 00 00 01 00 00 00 00 00 00 00 00 00 00 ee 17 d1 cf
```

TELEMETRY，Seq=2，Timestamp=1000，仅 temperature=25.0°C，30B：

```text
aa 55 01 02 00 00 00 02 00 08 00 00 00 00 00 00 03 e8 00 01 01 04 41 c8 00 00 3f e2 27 15
```

第二个向量只有一个指标，用于编解码单测；不能替代四指标性能负载。

## 6. 字节流与异常恢复

TCP/串口使用有界流解码器，算法见 LLD 第 2 节。先检查固定头和长度，再等载荷和 CRC；非法头、CRC 错或 2000ms 组帧超时，从候选 Magic 后一字节重新搜索。完整合法帧内的 AA 55 只是数据，不是新帧。

坏 CRC 不更新存活/指标时间、不入 DB。单个错帧 WARN 并计数，连续 5 个触发协议退化；连续 3 个有效帧恢复。帧错误不能导致崩溃或无限分配。无法识别 Version 按非法头重同步并计数，不能用 v1 载荷规则勉强解析。

## 7. UDP 约定

一个 UDP 数据报必须恰好包含一个完整 v1 帧，只接收 HEARTBEAT/TELEMETRY。不在不同报间拼接半帧；多帧合在一报、缺尾、超长均丢弃。4118B 是协议上限，大报可能 IP 分片；标准模拟报仅 54B，不宣称任意网络上无丢包。

按本地绑定端点+来源 IP/端口映射 device_id。同一本地端口共享一个 socket，来源映射不得冲突；未配置来源丢弃。UDP 不做控制命令、ACK 重传或可靠传输封装。

有效消息 Seq 用模差判断：d=(new-last) mod 2^32，0<d<2^31 为新，d=0 重复，其余旧/乱序；旧/重复不更新实时值、存活或落盘。统计缺口不等于证明网络丢包。失联 4000ms 后清除基准，第一条有效帧建立新基准，允许设备重启。协议 v1 不提供跨重启重放防护。

## 8. 联调检查顺序

先比对字节长度/偏移/端序，再比对 CRC 覆盖区与参数，随后检查 TLV 和序号关联，最后检查会话状态。日志可限量输出原始帧，不能靠同时修改两端来掩盖规范差异。
