# 01. PRD — C++/Qt 多源设备监控、数据采集与联调平台

> D1 · 2026-09-23 · 需求设计基线。保留全部必需功能，分阶段完善。

## 1. 产品背景
工业/测试/装备类软件经常需要同时接入多个设备，持续接收运行参数，完成状态监控、异常告警、日志记录、历史查询及联调。传统单脚本工具存在界面不统一、通信协议分散、问题难定位、数据不可追溯等问题。

本项目建设一个跨平台桌面客户端，统一多源设备接入、协议解析、实时监控、告警、历史存储与联调诊断，并以可复现的设备模拟器支撑测试。

## 2. 产品目标
### 2.1 核心目标
- 支持 TCP、UDP、串口三种设备接入方式。
- 支持至少 10 个模拟设备同时在线。
- 可实时显示设备状态、温度、压力、电压、转速等遥测数据。
- 支持历史数据落盘、查询和 CSV 导出；历史回放为可选。
- 支持阈值告警、断线告警和协议异常告警。
- 支持完整日志和错误码，便于问题定位。
- 支持 Windows 与 Ubuntu 构建运行。
- 建立从需求、设计、实现、测试到发布的文档闭环。

## 3. 非目标
MVP 不追求：
- 大规模分布式集群。
- 微服务架构。
- 华丽 3D 界面。
- 自研数据库。
- 复杂权限系统。
- 特定行业业务逻辑仿真。

## 4. 用户角色
### 4.1 系统操作员
- 查看设备在线状态。
- 建立/关闭连接。
- 查看实时数据、曲线和告警。
- 查询历史记录。

### 4.2 联调工程师
- 修改连接参数。
- 查看原始报文和解析结果。
- 发送控制指令。
- 查看通信日志和错误码。

### 4.3 软件开发/测试人员
- 运行模拟器。
- 注入异常报文。
- 执行自动化测试。
- 导出日志定位问题。

## 5. 典型使用流程
1. 启动客户端。
2. 加载设备配置。
3. 选择 TCP/UDP/串口设备并连接。
4. 客户端接收心跳与遥测报文。
5. 后台线程完成拆包、校验、解析。
6. UI 显示实时状态和曲线。
7. 数据写入 SQLite。
8. 超限数据触发告警。
9. 操作员发送控制指令。
10. 设备返回 ACK。
11. 断开后按策略自动重连。
12. 操作员导出日志/历史数据。

## 6. 功能需求
### F-01 设备管理
- 新增/编辑/删除设备配置。
- 设备字段：ID、名称、类型、连接方式、IP/端口或串口参数。
- 状态：Disconnected / Connecting / Online / Degraded / Reconnecting / Fault。

### F-02 TCP 客户端通信
- 连接远端设备。
- 异步收发。
- 心跳机制。
- 断线重连。
- 连接超时。
- 粘包/半包处理。

### F-03 UDP 通信
- 监听指定端口。
- 支持单播数据。
- 可选广播发现。

### F-04 串口通信
- 枚举串口。
- 配置波特率、校验位、停止位。
- 异步接收。
- 可选接入 STM32/ESP32。

### F-05 协议解析
- 固定帧头。
- 协议版本。
- 消息类型。
- 序列号。
- 载荷长度。
- 时间戳。
- CRC32。
- 未知消息类型安全忽略并记录日志。

### F-06 实时监控
- 设备列表。
- 当前值。
- 最近更新时间。
- 实时曲线。
- 在线/离线状态。

### F-07 告警
- 上下限阈值。
- 断线告警。
- CRC 错误告警。
- 数据长时间不更新告警。
- 告警确认。

### F-08 历史数据
- SQLite 存储。
- 按设备、指标、时间段查询。
- CSV 导出。
- 可选历史回放。

### F-09 日志
- DEBUG/INFO/WARN/ERROR。
- 日志滚动。
- 关键操作日志。
- 原始报文调试日志可开关。

### F-10 控制指令
- 通过 TCP/串口发送；UDP 阶段仅接收遥测，不承诺可靠控制。
- Start / Stop / Reset / SetParameter。
- 命令序列号。
- ACK/超时。
- 命令记录。

### F-11 模拟设备
- 同时启动多个虚拟设备。
- 可设置采样周期。
- 可注入：丢包、断线、CRC 错误、异常值、延迟。

### F-12 配置管理
- JSON/INI 配置。
- 配置校验。
- 无效配置提示。

### F-13 可选 AI 异常检测
- Python 训练小模型。
- 导出 ONNX。
- C++ ONNX Runtime 推理。
- 实时输出异常分数。
- 与规则告警并行存在。

## 7. 非功能需求
### NFR-01 稳定性
10 设备 × 10Hz × 4 指标连续运行 8 小时，无崩溃、无死锁，内存与队列有界；量化判定见 [测试计划第 3 节](07_TEST_PLAN.md)。

### NFR-02 性能
最终必需基线：10 设备 × 10Hz × 4 指标，UI 与采集解耦；100ms GUI 探针额外延迟 P95≤100ms、最大≤500ms。门槛和环境记录见测试计划。

### NFR-03 可维护性
通信、协议、业务、存储、UI 分层，不允许所有逻辑集中在 MainWindow。

### NFR-04 可测试性
协议解析、CRC、状态机、告警规则、数据库 DAO 可独立测试。

### NFR-05 可移植性
Windows 11 与 Ubuntu 24.04 均可构建。

### NFR-06 可诊断性
所有连接、断开、重连、协议校验失败、数据库异常必须产生日志。

## 8. 实施阶段与范围

“阶段可演示”不等于“全部功能完成”。F-01 至 F-12 的必需项均保留；广播发现、STM32/ESP32 实物、回放、F-13 AI 为可选，不阻塞主线。状态均为 Planned。

| 阶段 | 交付内容 | 出口条件 |
|---|---|---|
| S1 | CMake、Frame/Codec/CRC | 工程可编译；协议向量与异常边界单测 |
| S2 | TCP simulator、TcpTransport、Session 基础、日志 | 可复现单设备/多设备收发与错误 |
| S3 | 状态机、心跳、重连、控制/ACK、退出 | 单元/集成验证超时、人工停止、过期事件隔离 |
| S4 | 最小 UI、设备/配置管理、实时曲线 | 三设备演示、四指标可见、配置校验 |
| S5 | SQLite、历史/CSV、命令记录 | 事务/失败/查询/版本验证 |
| S6 | 阈值、失联、陈旧、CRC 告警与确认 | 触发/恢复/确认/去重测试 |
| S7 | UDP、串口、对应模拟与异常 | 两种传输各有集成证据 |
| S8 | 全链路、Windows/Ubuntu、部署验收 | 全部必需需求闭环、负载与稳定性报告 |

## 9. 最终必需功能验收条件
- Windows 可构建运行。
- Ubuntu 可构建运行。
- 阶段冒烟：3 个以上模拟设备稳定连接 30 分钟。
- 最终验收：10 个 TCP 模拟设备各 10Hz、四指标，完成 30 分钟性能和 8 小时稳定性测试；UDP/串口分别完成集成验收。
- TCP 拆包正确处理粘包/半包。
- 设备数据实时显示。
- SQLite 历史查询正常。
- 至少 20 个自动化测试通过，并覆盖全部必需需求和关键异常边界，数量不能替代覆盖。
- TCP/串口四命令及 ACK/超时验证；UDP 来源隔离和乱序/重复处理验证。
- 阈值/断线/CRC/陈旧告警、确认/恢复、配置管理、日志滚动与 CSV 导出通过。
- 在默认配置与受控环境下，停止有效发送后 5 秒内发现失联；端点稳定恢复后 15 秒内自动上线；人工断开不自动重连。
- CRC 错误不会导致程序崩溃。
- 提供需求、设计、测试、用户文档。
