> 2026-09-26 冒烟记录：10 台设备实测通过「启动全 Online → 强杀模拟器（≤5s 全部 Reconnecting、失败按真实原因 CONNECT_TIMEOUT 归因退避）→ 重启模拟器自动恢复 Online → 优雅关闭无残留」全链路。期间发现并修复 S3 缺陷：重连点火未清上一轮连接的打开时刻，异步建链期间首个轮询周期即误报「无首帧超时」（回归用例 `reconnectAttemptNotKilledByStaleOpenTimestamp`）。

```bat

build\simulator\dms_simulator.exe -c 10 -p 9001
```

界面（S4 最小 UI，单窗口）：左侧设备列表（名称 + 状态文字/色点 + 最近遥测时间），右侧选中设备的四指标曲线（temperature °C / pressure kPa / voltage V / rpm r/min，600 点/指标，100ms 合并刷新）；工具栏「全部连接 / 全部断开 / Reset / 采样周期(ms)+应用周期」；状态栏显示在线计数与命令结果。Reset=命令 3（无参），采样周期=命令 4 SetParameter（参数 id=1 uint32 大端，100–1000ms）。

## 1. 使用前提

使用匹配 Windows 11 或 Ubuntu 24.04 的发布包，核对发布说明、文件校验值和已知限制。当前发布包的构成与验证状态（S8）：

| 项目 | 状态 |
|---|---|
| Qt/编译器/CMake 精确版本 | 双环境实测记录见 [S8 跨平台证据](16_S8_CROSS_PLATFORM_EVIDENCE.md)；SQLite 引擎版本随"数据库就绪"日志在每次启动留痕 |
| 客户端/模拟器文件名与启动参数 | `bin/dms_monitor`（`--config-dir <dir>` 可选，指定独立运行根）与 `bin/dms_simulator`（`--help` 查看全部参数）；配置模板位于 `bin/config/`，首次启动复制到运行根，已存在不覆盖 |
| Windows 平台/SQL/串口插件 | 发布包经 windeployqt 携带 platforms/sqldrivers/串口库与 VC 运行库（`scripts\package.bat`），独立运行验证见证据文档 |
| Ubuntu 动态库与权限说明 | Linux 包不带 Qt 库，部署机需安装系统依赖（qt6-base、qt6-serialport、SQLite 驱动，见证据文档的 apt 清单）；安装目录可只读，运行期数据全部落在运行根 |
| 构建、CTest 与打包命令 | Windows：`scripts\build.bat [Debug\|Release]`、`scripts\package.bat`；Linux：`scripts/build.sh [Debug\|Release]`、`scripts/package.sh`；打包产物在 `dist/` |

不能把“安装 Qt Runtime”当作完整部署步骤，发布包应经过独立运行验证。

## 2. 首次启动与配置

运行后先在 Diagnostics 查看实际数据根目录。config、data、logs、exports 位于用户可写目录，见 [配置契约](15_CONFIGURATION.md)。首次初始化模板不覆盖已有配置。数据库失败需查看 DB 错误，不能自行删除数据库尝试修复。

新增设备：填写唯一 ID、名称和通信类型；TCP 填 host/port，UDP 填本地绑定及允许来源，串口从枚举列表选择端口并设置通信参数。ID 用于历史关联，不作为可随意改名的显示字段。非法字段给出定位提示；在线修改先断开该设备。

## 3. 连接与状态

Devices 点击 Connect，进入 Connecting；收到有效数据后进入 Online，数据陈旧/连续协议错误时为 Degraded；失联后为 Reconnecting；无效配置为 Fault。仅 TCP 连接成功而未收到有效帧不能显示 Online。

Disconnect 会停止自动重连。设备断电/模拟器关闭等意外断线才自动恢复。UDP 的“连接”表示监听绑定和接收活性，无 TCP 握手过程。

## 4. 遥测与控制

Telemetry 显示温度 °C、压力 kPa、电压 V、转速 r/min 与曲线。无数据时标陈旧/未知，不把旧值伪装为实时值。界面刷新与采集频率不同属于正常设计。

TCP/串口可发 Start/Stop/Reset/SetParameter；SetParameter 设模拟器采样周期 100–1000ms。Reset 复位模拟业务并恢复采集，不重启协议连接。UDP 控制入口禁用。

命令显示等待、成功、拒绝、超时、取消或失败。超时意味着结果未知，不能认为设备一定未执行；检查日志后再决定是否人工重发。Stop 停遥测但保留心跳，此时不因遥测停止而发陈旧告警。

## 5. 告警、历史与导出

Alarms 确认表示“已知悉”，不会消除异常，也不会删除记录；恢复时间单独显示。持续越界不逐帧重复生成，恢复后再越界才新建事件。

History 选择设备/指标与时间范围，使用客户端接收时间、起点包含终点不包含；界面显示本地时间并明确时区，保存/导出用 UTC 毫秒。历史时间与设备时间不同不直接认定为丢数据。CSV 导出以完成提示为准，取消或写失败不算成功。删除设备配置仍保留历史。

## 6. 正常退出

程序先停采集，再排空待写数据。磁盘异常导致无法排空时显示未提交数量，可继续等待或取消退出。不要用“任务管理器结束进程”替代正常关闭并假设数据已保存。

## 7. 常见问题

| 现象 | 检查路径 |
|---|---|
| 无法连接 | 模拟器/端点、IP/端口、防火墙规则、CONNECT_TIMEOUT；不建议直接关闭系统防火墙 |
| Online 但数值不更新 | 是否 Stop、指标更新时间、发送频率、FRAME_PAYLOAD/CRC；心跳不等于遥测 |
| UDP 无数据 | bind 与 peer 配置、源端口、未知来源计数；检查一报一帧 |
| 串口打不开 | 是否占用、端口是否变化、参数/权限；不自动修改系统权限 |
| DB 写失败/丢样本增加 | 磁盘空间、写权限、锁等待、队列；保存日志，勿删除旧库 |
| 启动提示新版本数据库 | 使用匹配应用或已验证迁移，禁止降版本覆盖 |
| 退出等待 | 查看队列和 DB 错误；继续等待或取消退出，避免强杀 |

反馈问题时提供版本/hash、OS、操作步骤、预期/实际、相关错误码/日志和故障时间。原始 RX/TX 仅按需开启，注意截断标记。

## 8. 基本人工作业验收

1. 启动三个 TCP 模拟端点，创建/导入对应配置并连接。
2. 核对四指标、单位、状态；运行 30min。
3. 停掉一个模拟器，确认≤5s 失联，其余设备继续。
4. 恢复端点，确认≤15s 自动上线；再人工断开，确认不自动重连。
5. 注入坏 CRC/高温，确认日志、告警、恢复和确认历史。
6. 查历史并导出 CSV，核对过滤与条数；正常退出后重启再查询。
7. S7 分别完成 UDP 与串口测试；完整负载/8h 与部署以测试计划为准。
